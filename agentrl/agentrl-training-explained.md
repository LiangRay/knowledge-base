# AgentRL 训练全解：从厨师类比到 Expert Distillation

> 讨论时间：2026-09-15  
> 主题：用通俗的方式理解 Agent 强化学习训练的完整流程

---

## 一、为什么需要 AgentCore + Code Interpreter

### 核心问题

RL（强化学习）训练需要 Agent **大量并行试错**，每次试错都需要一个隔离的执行环境。

### 类比：训练新手厨师

- **没有 AgentCore**：只有一个厨房，64 道菜排队做 → 30 分钟/轮
- **有了 AgentCore**：一口气开 64 个独立厨房，同时做 → 30 秒/轮

```
          RL 训练框架（老师）
              │
    ┌─────────┼─────────┐
    ▼         ▼         ▼
 厨房1      厨房2  ... 厨房64       ← AgentCore Session
 番茄炒蛋   蛋炒饭     红烧肉       ← 不同任务
    ↓         ↓         ↓
  同时做！  同时做！   同时做！      ← Code Interpreter 执行代码
    ↓         ↓         ↓
  6分       3分        8分          ← 奖励函数打分
```

### 各组件职责

| 组件 | 职责 | 类比 |
|---|---|---|
| **RL 训练框架** (veRL / OpenRLHF) | 编排循环，调度采样，更新模型 | 老师 |
| **AgentCore Runtime** | 管理 64 个并行 Session 的生命周期 | 厨房管理员 |
| **Code Interpreter** | 每个 Session 里的沙箱，执行代码并返回结果 | 厨房里的设备 |
| **策略模型 (LLM)** | 被训练的对象，越来越会写代码 | 新手厨师 |

## 二、轨迹（Trajectory）是什么

**轨迹 = Agent 从头到尾做一道题的全部操作记录。**

每一步记录三个东西：看到了什么、做了什么、结果是什么。

### 代码 Agent 的例子

```
题目: 用 Python 算斐波那契数列第10项

第1步: LLM 生成代码 → def fib(n): return fib(n-1) + fib(n-2)
       Code Interpreter 执行 → ❌ 报错：递归没有终止条件

第2步: LLM 看到报错，修改 → 加了 if n <= 1: return n
       Code Interpreter 执行 → ✅ 输出 55，正确！
```

```python
轨迹 = [
    (观察: "题目文本",     动作: "第一版代码",  结果: "报错"),   # 第1步
    (观察: "报错信息",     动作: "修复代码",    结果: "通过"),   # 第2步
]
```

## 三、奖励函数跑在哪里

### 两种模式

**模式 A：简单奖励 → 跑在训练框架里**

比如判断代码输出是否等于正确答案，比个字符串就行：

```python
def reward_function(题目, 代码, 执行结果):
    if 执行结果 == 正确答案:
        return 1.0
    else:
        return 0.0
```

**模式 B：复杂奖励 → 跑在 AgentCore 沙箱里**

需要实际执行才能验证的场景：

```
AgentCore Session
┌──────────────────────────────────┐
│ LLM 写爬虫代码                    │
│ Code Interpreter 执行爬虫         │
│           ↓                       │
│ Code Interpreter 执行奖励函数     │
│   ├─ 爬到了数据吗？    → +0.3    │
│   ├─ 数据格式对吗？    → +0.2    │
│   ├─ 有没有处理异常？  → +0.2    │
│   ├─ 爬取速度合理吗？  → +0.15   │
│   └─ 没有触发反爬吗？  → +0.15   │
│   返回总分: 0.85                  │
└──────────────────────────────────┘
```

### 需要在沙箱里跑奖励的典型场景

| 任务 | 奖励怎么算 | 为什么要在沙箱里 |
|---|---|---|
| 写 CLI 工具 | 跑单元测试，看通过率 | 要实际执行测试 |
| 生成 SQL 查询 | 在数据库上跑，比对结果 | 要连数据库 |
| 写数据分析脚本 | 跑脚本，检查输出图表 | 要执行 pandas/matplotlib |
| 操作 Linux 系统 | 检查文件/进程/权限 | 要在真实环境里检查 |

**本质**：奖励函数就是一段代码，放哪里跑取决于它需不需要"动手验证"。

## 四、LLM 就是被强化的对象

整个 RL 的目的：**让 LLM 越来越会做任务**。

### "强化"的含义

```
第 1 轮: LLM 写了 64 份代码
         ├─ 第 5 份写得好，高分
         └─ 其他都不行
    → GRPO: 往第 5 份的写法靠拢

第 2 轮: 稍微好一点，10 份高分
    → GRPO: 继续强化

...
第 5000 轮: 大部分都能写对了 🎉
```

**不是靠人教的，是靠自己试错、被打分、然后调整。**

### 对比三种训练方式

| 训练方式 | 怎么教 LLM | 类比 |
|---|---|---|
| **预训练** | 读海量文本，学语言规律 | 读了一万本菜谱 |
| **SFT（监督微调）** | 给标准答案，照着学 | 老师手把手教做每道菜 |
| **RL（强化学习）** | 不给答案，自己做，做完打分 | 自己做菜，尝了再改进 |

RL 的厉害之处：能发现人类没有写过的解法。DeepSeek-R1、OpenAI o1 这些推理模型都用了 RL。

## 五、Computer Use 也可以用 RL 训练

把"写代码"换成"操作电脑"，逻辑完全一样。

| | 代码 Agent | Computer Use Agent |
|---|---|---|
| 看到什么 | 题目文本、报错信息 | **屏幕截图**（图片） |
| 做什么 | 写代码 | **点击坐标 (x,y)、打字、滚动** |
| 在哪执行 | Code Interpreter | **虚拟桌面 / 浏览器沙箱** |
| 怎么打分 | 代码结果对不对 | 任务完成了没有 |

### Computer Use RL 训练架构

```
RL 训练框架
  │ 开 64 个并行虚拟桌面
  ▼
┌──────────┐ ┌──────────┐     ┌──────────┐
│ 桌面 1    │ │ 桌面 2    │ ... │ 桌面 64   │
│ 任务:订票 │ │ 任务:填表 │     │ 任务:发邮件│
│ LLM看截图 │ │ LLM看截图 │     │ LLM看截图  │
│ → 点鼠标  │ │ → 点鼠标  │     │ → 点鼠标   │
│ → 新截图  │ │ → 新截图  │     │ → 新截图   │
│ ... 多轮  │ │ ... 多轮  │     │ ... 多轮   │
└─────┬────┘ └─────┬────┘     └─────┬────┘
      ▼            ▼                ▼
   GRPO 更新 LLM（学会更准确地操作）
```

### Computer Use RL 的挑战

| 挑战 | 原因 |
|---|---|
| 观察空间巨大 | 截图 (MB) vs 文本 (KB)，信息量差 100 倍 |
| 动作空间连续 | 鼠标坐标 (x,y) 是连续值，搜索空间大 |
| 一步错步步错 | 点错按钮，后面页面全变了 |
| 反馈延迟长 | 操作 20 步才知道成没成功 |
| 沙箱更重 | 虚拟桌面 (GB) vs 代码沙箱 (MB)，并行成本高 |

### 相关项目

| 项目 | 做了什么 |
|---|---|
| OpenAI Operator | Computer Use Agent，据传用了 RL |
| Anthropic Claude CU | 目前主要靠 SFT，在探索 RL |
| DigiRL (UC Berkeley) | 专门用 RL 训练 GUI Agent |
| WebArena / VisualWebArena | 网页操作 Agent 的标准 benchmark |
| OS-World | 跨操作系统的 Computer Use benchmark |

## 六、Expert Distillation — 用强模型生成轨迹训练小模型

### 核心思路

用 Claude/GPT-4 当老师生成高质量轨迹，训练一个便宜的小模型。

```
Claude Sonnet（老师，强但贵）
  │ 做 10000 道题，记录每步操作
  ▼
10000 条高质量轨迹
  │ 训练小模型
  ▼
小模型 7B/14B（学生，便宜能部署）
```

### 两种用法

**用法 1：纯 SFT（模仿学习）**

直接拿 Claude 的轨迹当标准答案，教小模型模仿。

**用法 2：SFT + RL（更强，业界标准做法）**

```
阶段 1: Claude 轨迹 → SFT → 小模型 v1（能做对 40%）
                              │
阶段 2: RL 自我强化 → 小模型 v2（能做对 70%，可能超越老师）
```

**为什么不直接上 RL？**

小模型一开始啥都不会 → 瞎写代码 → 全是 0 分 → 没有正向信号 → 训练崩了。

先用 Claude 轨迹 SFT 学会基本套路，再用 RL 自我探索提升。

> 类比：不能让没进过厨房的人直接"自由探索"学做菜。得先让大厨示范几遍（SFT），学会基本操作后，再自己探索改进（RL）。

### 具体流程

```python
# 第一步：用 Claude 批量生成轨迹
trajectories = []
for task in 10000个任务:
    session = agentcore.create_session()
    history = []
    while 任务没完成:
        action = claude_api.generate(task, history)
        result = session.code_interpreter.run(action)
        history.append((action, result))
    trajectories.append(history)

# 第二步：SFT 训练小模型
small_model.sft_train(trajectories)

# 第三步：RL 继续提升
small_model.rl_train(algorithm="GRPO", env=agentcore)
```

### 谁在这么做

| 项目 | 方法 |
|---|---|
| DeepSeek-R1 | DeepSeek-V3 生成推理轨迹 SFT + GRPO |
| OpenAI o1/o3 | 据传用强模型 CoT 轨迹 + RL |
| Qwen-Agent | GPT-4 生成工具调用轨迹训练小模型 |
| AgentTrek (UIUC) | GPT-4V 生成 Computer Use 轨迹训练小模型 |
| FireAct (Princeton) | GPT-4 生成 ReAct 轨迹微调 Llama |

## 七、完整训练管线总结

```
预训练（读书学语言）
  ↓
SFT — 用 Claude 轨迹（跟大厨学基本功）
  ↓
RL — GRPO 自我强化（自己做菜，打分改进）
  ↓
部署小模型（便宜又好用）
```

**一句话**：强模型当老师示范 → 小模型模仿学习 → 小模型自我强化 → 部署上线。这就是当前业界训练 Agent 的标准三段式。
